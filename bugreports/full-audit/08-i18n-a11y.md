# Internationalisation & accessibility (whole site)

Audited: `src/i18n/routing.ts`, `src/i18n/navigation.ts`, `src/app/[locale]/layout.tsx`,
all eleven `messages/*.json`, `src/components/LanguageSwitcher.tsx`, `Header.tsx`,
`Footer.tsx`, and every page/component under `src/app/[locale]/` plus the
components they render (`badges/*`, `games/*`, `stats/*`, `account/*`, `compare/*`,
`charts/*`, `admin/*`). Prior rounds (`bugreports/acp-bugs/VERIFIED.md`,
`bugreports/AGENT-AUDIT.md`, `FIXES.md`, `agent-09-i18n.md`, `agent-19-ui-shell.md`)
were read first; their fixed items are not re-reported.

Method (everything below was scripted, not eyeballed):

- Flat-key diff of all 11 message files: key sets, ICU argument names, duplicate
  JSON keys in the raw text (own recursive-descent scanner), and JSON structure.
- Value-space closure for **every** dynamic key site: extracted the possible
  values from source (`FAQ_KEYS`, `GAMES`, `RARITY_TIERS`, `ACHIEVEMENT_CATEGORIES`,
  `FeedKind`, `StaffRole`, `AdminShell.TABS`, `ProfileCustomizer` field list) and
  checked each against the flat message map of all 11 locales.
- Live **read-only** `SELECT` over the session pooler (`.env.local`) for the
  DB-driven value spaces: distinct `activity_events.kind`, `profiles.role`,
  `badges.status`.
- `grep`/AST-ish scans for JSX text literals (single- and multi-line), literal
  `aria-label`/`placeholder`/`title` attributes, `onClick` on non-interactive
  tags, `<img>` without `alt`, `<input|select|textarea>` without a label, arrow
  glyphs, physical CSS properties (utilities, inline styles, `globals.css`), and
  buttons with no accessible name.
- Read `next-intl@4.14.5`'s own navigation source (`dist/esm/.../createNavigation.js`,
  `navigation/shared/utils.js`) to settle what a locale switch does with a query string.
- Could not run: a browser/AT pass, so the RTL bidi and focus items are reasoned
  from spec behaviour and marked accordingly. `tsc`/`eslint` were not needed.

Nothing was modified; the only file written is this report.

## Clean (stated so "nothing" means something)

- **Key parity: 1022 keys × 11 locales, identical key sets, 0 missing / 0 extra in
  every locale; 0 ICU argument mismatches (`{count}` vs `{n}` etc.); 0 duplicate
  JSON keys in any file's raw text.** The plural differences that a naive diff
  flags (`one/other` in `en` vs `other`-only in `zh`/`ja`/`ko`, `one/few/many` in
  `ru`, `zero/one/two/few/many` in `ar`) are correct CLDR categories, not bugs.
- **Every dynamic key resolves in all 11 locales**: FAQ 20 ×`{k}Q/{k}A`,
  13 games ×`{id}Title/{id}Desc`, 3 achievement categories, 6 rarity tiers,
  13 feed kinds, 3 roles + 3 hints, 10 admin tabs, 38 customizer labels/hints.
  No `t.has()` fallback is missing anywhere, because no value space is open.
- **The DB-driven value spaces are closed in the live data**: `activity_events.kind`
  ∈ {achievement, level_up, daily, wheel} ⊂ `FeedKind`; `profiles.role` = {user}
  (and `RoleBadge` is behind `isStaffRole`); `badges.status` ∈ {active, expired,
  upcoming} ⊂ the 4-value check constraint (`0001_init.sql:77`) = `BadgeRow["status"]`.
- **0 literal `t("key")` calls whose key is missing from every namespace of their
  file; 0 `t("key")` calls missing an ICU argument their message requires.**
- **RTL**: `<html lang={localeHtmlLang[locale]} dir={isRtl(locale)?"rtl":"ltr"}>`
  (`layout.tsx:96-97`); all 13 arrow glyphs carry `.dir-arrow`, which the CSS
  mirrors under `[dir="rtl"]` (`globals.css:1368-1371`); `[dir="rtl"]` overrides
  exist for the bar/sheen/rank/marquee animations (`globals.css:1228, 1375-1376,
  1930-1932`). No physical `ml-/mr-/pl-/pr-/text-left/text-right/border-l/-r`
  utilities, no physical margins/paddings in `globals.css`, and no
  `textAlign`/`marginLeft` inline styles (the only physical inline coordinates
  are game-object `left/top` on a physical play field).
- **Heading structure**: every page renders exactly one `<h1>`. `active`, `badges`,
  `expired`, `upcoming` delegate to `BadgeExplorer.tsx:64`; the files that show a
  second `<h1>` (`account`, `games/[game]`, `inventory`, `auth/callback`) are
  mutually exclusive render branches, not duplicates. No page skips a level.
- **Link/i18n routing**: no `next/link` import anywhere, no locale-prefixed
  hardcoded `href` (all raw `<a href>` are external URLs or the XML API route),
  all 11 `/public/flags/*.png` present, `localeNames`/`localeHtmlLang` are
  `Record<Locale,…>` so TS enforces completeness.
- **Forms**: every `<input|select|textarea>` under `[locale]` is either wrapped in
  a `<label>` or carries `aria-label` — with the single exception in B10.
- Locale switching **does** preserve the query string: `getPathname` in
  next-intl 4.14.5 passes a string href through unchanged when no `pathnames`
  config is set (`navigation/shared/utils.js` → `compileLocalizedPathname` →
  `compiled = value`), so `pathname + window.location.search` reaches
  `router.replace` intact. No bug here (this was the earlier `i18n-1`).

## B1 — The /account customizer is English in all ten non-English locales: 33 hard-coded option labels and 4 placeholders

- **Severity**: medium
- **Confidence**: high (read + mechanical check that no key exists)
- **Where**: `src/components/account/ProfileCustomizer.tsx:84,85,86,88,90,98,113,114` (option labels); `:79,96,97,112` (placeholders); rendered at `:220` and `:175`
- **Code**:
  ```tsx
  { key: "font", kind: "select", label: "font", options: [["sans","Sans"],["serif","Serif"],["mono","Mono"],["rounded","Rounded"]] },
  { key: "density", kind: "select", label: "density", options: [["cozy","Cozy"],["compact","Compact"]] },
  ...
  {field.options.map(([optionValue, optionLabel]) => (
    <option key={optionValue} value={optionValue}>{optionLabel}</option>
  ))}
  ```
- **Why it is wrong**: the option **label** is the string shown to the user, and it
  is a literal — the surrounding `label`/`hint` go through `t()` but the values do
  not. No message key exists for any of them (`messages/en.json` has no
  `customizer.Sans`/`.Serif`/`.Cozy`/`.Compact`/… — checked mechanically, and
  `grep -l "Sans\|Cozy" messages/` returns nothing). A `/de/account`, `/ja/account`
  or `/ar/account` visitor therefore gets an English dropdown set inside an
  otherwise translated form: Sans/Serif/Mono/Rounded, Glass/Solid/Outline,
  Sharp/Soft/Round, None/Ring/Double/Glow/Crown, Grid/Row/Carousel,
  Cozy/Compact, Auto/Violet/Emerald/Sapphire/Gold, Off/Subtle/Full, and the
  placeholders "Badge Hunter", "username" ×2, "hunting SUBtember…". AGENTS.md
  requires every UI string to come from `messages/<locale>.json`; this is the one
  user-facing control that escapes that rule.
- **How to reproduce**: open `/de/account` (Profile customizer). The selects read
  "Solid", "Cozy", "Crown"; the title field's placeholder reads "Badge Hunter".
- **Suspected cause**: the option tuples and placeholders were authored as data,
  so the earlier message-file sweeps (which only diff `messages/*.json`) could not
  see them.

## B6 — `CatcherGame` and `ShootGame` are pointer-only: no keyboard path at all

- **Severity**: low
- **Confidence**: high (no keyboard handler exists anywhere in `src/components/games/`)
- **Where**: `src/components/games/CatcherGame.tsx:139` (`onMouseMove={move}` on the play area), `src/components/games/ShootGame.tsx:138` (`onClick={shoot}` on a `<div>`)
- **Code**:
  ```tsx
  <div
    ref={areaRef}
    onClick={shoot}
    className={`relative h-80 select-none overflow-hidden … ${running ? "cursor-crosshair" : ""}`}
  >
  ```
- **Why it is wrong**: the only way to move the basket / hit a target is a pointer
  event on a non-focusable `<div>` (`grep -rn "onKeyDown|tabIndex|addEventListener" src/components/games/*.tsx`
  returns nothing). A keyboard user can press "Start" (a real button) and then has
  no way to play, so both games consume a bet and always end in a loss-shaped
  outcome. `CatcherGame` also uses `onMouseMove` rather than `onPointerMove`, so a
  touch/pen user cannot move the basket either. The other eleven games are driven by
  real buttons and are unaffected.
- **How to reproduce**: tab to `/en/games/catcher`, press Enter on Start, then try
  any key — the basket never moves.
- **Suspected cause**: the play area was wired to raw mouse/click events.

- **Severity**: low
- **Confidence**: high
- **Where**: `src/components/Header.tsx:118-131` (desktop nav) and `:245-259` (mobile nav); the predicate `isActive()` at `:65-70`

## B8 — Switching language drops keyboard focus (the trigger is disabled while the transition is pending, after focus was moved to it)

- **Severity**: low
- **Confidence**: medium-high (mechanism is spec-determined; not exercised with a browser)
- **Where**: `src/components/LanguageSwitcher.tsx:179` (`disabled={isPending}`) with `:124-135` (`select`)
- **Code**:
  ```tsx
  function select(next: Locale) {
    setOpen(false);
    triggerRef.current?.focus();        // focus goes to the trigger …
    if (next === locale) return;
    startTransition(() => { … router.replace(`${pathname}${search}`, { locale: next }); });
  }
  …
  disabled={isPending}                  // … which is then disabled for the duration
  ```
- **Why it is wrong**: an element that becomes disabled while focused loses focus to
  `<body>`, so a keyboard user who picks a language with Enter is dropped at the top
  of the document when the navigation settles and must tab through the header again —
  the very focus return the first line intends to provide is undone by the
  `disabled` attribute. Escape and outside-click both return focus correctly
  (`:112`, `:126`); only the "select" path loses it. (`aria-disabled`/`data-pending`
  styling would keep it focusable.)
- **How to reproduce**: keyboard-only: focus the flag button, ArrowDown, ArrowDown,
  Enter — after the page re-renders, `document.activeElement` is `<body>`.
- **Suspected cause**: `disabled` was chosen to block double-switching.

## B10 — RTL: a leading `+`/`-` on coin amounts renders on the wrong side in Arabic

- **Severity**: low
- **Confidence**: medium — reasoned from UAX#9 neutral resolution, **not** rendered in a browser
- **Where**: `src/components/FeedList.tsx:141`, `src/components/WheelOfFortune.tsx:137`, `src/components/games/SlotsGame.tsx:107`
- **Code**:
  ```tsx
  {/* FeedList.tsx:139-142 */}
  <span className={`inline-flex items-center gap-1 font-bold ${event.coins_amount > 0 ? "text-success" : "text-danger"}`}>
    {event.coins_amount > 0 ? "+" : ""}{event.coins_amount.toLocaleString(locale)} <Coin size={12} />
  </span>
  ```
- **Why it is wrong**: `+`/`-` are bidi-neutral (ES/ON). In an RTL paragraph with no
  strong LTR character in the run, the neutral takes the paragraph direction and is
  placed at the right end of the number run, so `+1,234` is painted `1,234+` (and a
  negative `-1,234` as `1,234-`) for `ar`. The `<Coin>` sibling is an SVG, not text,
  so nothing in the span provides LTR context — which is why the adjacent
  `+{xp_amount} XP` at `FeedList.tsx:138` is *not* affected (the literal "XP" is
  strong LTR and anchors the run). The same shape appears on the wheel result and
  the slots result. Not user-blocking, but an Arabic reader sees the sign on the
  wrong side of the amount.
- **How to reproduce**: `dir="rtl"` on `/ar/feed` and inspect a coin event (or add
  `&#x200F;`/a `dir="ltr"` span and watch the sign move).
- **Suspected cause**: the sign is concatenated into the same text run instead of
  being isolated (no `dir="ltr"` / RLM on the numeric island).
