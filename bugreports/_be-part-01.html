Performance Quick Win

A hard timeout on every catalog read

Details

Every query in src/lib/queries.ts goes out with no abort signal, so one slow Supabase pooler response holds the whole server render until the platform kills it, producing a 504 instead of the empty state the .catch() wrappers were written for. Pass AbortSignal.timeout on the PostgREST reads (about 2500 ms, from a setting) and let the existing fallbacks render the empty state. Effort: S. Risk if built badly: too tight a limit turns a merely busy database into a site that looks empty, so log every abort with its label so the rate is visible before the value is tuned. Why: A pooler hiccup should degrade the catalog to an empty state with a logged cause, not hand every visitor a gateway timeout. Source: new-ideas-08-performance.json

Bedienbarkeit Quick Win

Sortable tables with aria-sort

Details

The data tables on the leaderboards, the compare view and the admin panels are static text. Make the header cells sortable with a real button inside each sortable header cell, set the sort attribute on the active column, announce the change politely, and put the sort key and direction in the URL so a sorted view is shareable and survives a reload. Effort: M. Risk if built badly: client sorting reorders only the rows that were fetched and silently lies about the ranking, so either sort server-side or label it as sorting the current page. Why: A leaderboard you cannot reorder makes the visitor do the sorting in their head. Source: new-ideas-09-usability.json

Bedienbarkeit Quick Win

Time-display preference with a zone label

Details

Deadlines are formatted on the server with the locale but no time zone, so a visitor in Seoul reads the server's clock as if it were their own. Format dates on the client, or pass the request offset, with a three-way preference of relative, local absolute and UTC; show a small UTC offset label beside every deadline, and put the exact instant in the element's title. Store the preference alongside the locale cookie. Effort: M. Risk if built badly: client-only formatting mismatches the server HTML and flickers on hydration, and a zone label derived from a guess is worse than none, so it must come from the offset actually used. Why: A deadline that is silently in another time zone is the most expensive kind of usability bug on a drop-tracking site. Source: new-ideas-09-usability.json

Bedienbarkeit Quick Win

Language attributes on catalog strings

Details

Badge titles, descriptions, categories and how-to-earn text come from Twitch in English, but a Japanese or Arabic page renders them with no language signal, so a screen reader reads English words with the wrong voice. Mark catalog-sourced text with the source language attribute and leave member-entered text such as display names, bios and status lines on their own locale, driven by a flag on the row rather than a blanket attribute. Add a short note in the language switcher explaining that catalog content is English. Effort: S. Risk if built badly: marking a localised or loanword name as English makes pronunciation worse, and a blanket attribute on all text is actively harmful. Why: Ten of eleven locales display English catalog text, and a mixed-language page is exactly where assistive technology gets it wrong. Source: new-ideas-09-usability.json

Badges Quick Win

Unified site search (badges, blog, FAQ)

Details

One search box in the header (or a Cmd/Ctrl-K command palette) that queries badges by name/set id/category, blog posts by title, and FAQ entries, and shows a grouped result list with keyboard navigation. Today each surface has its own scoped search, so users have to guess where to look. Why it fits: All three corpora already exist in Postgres with text columns; the catalog has `name`, `set_id`, `category`, and the blog/FAQ rows are plain text. Cross-surface search is table stakes for a content site of this size. Effort: M. Risk if built badly: Unescaped `%`/`_` in an ILIKE query (a documented past incident) silently returns everything, and an unindexed scan over the catalog makes the palette laggy on every keystroke — needs debounce + trigram index. Source: bugreports/agent-idea-03.md

Content Quick Win

IndexNow ping on publish

Details

When a post, glossary entry, tutorial or refreshed badge page is published, the publish path submits the affected URLs to IndexNow and warms those routes' cache, so new content is discovered in hours instead of at the next sitemap crawl. The publish action already knows the exact slugs it touched, so this is one outbound request from the existing route handler, deduplicated by URL and capped per run, with failures logged as a heartbeat rather than blocking the publish. Data: the slugs written by the publish action plus the canonical host. Effort: S. Risk if built badly: a loop or a bulk sync submits thousands of URLs and the endpoint throttles the host; cap per-run submissions and never ping from a catalog sync, only from an editorial write. Why: Editorial content is only worth writing if it is indexed while the drop it describes is still live. Source: new-ideas-02-content.json

Design Quick Win

One snap rail primitive for horizontal strips

Details

Several surfaces scroll sideways with ad-hoc markup, the showcase carousel, rarity leaders and the trending strips, and each handles edge fade, snapping and keyboard differently. Define one rail primitive: scroll-snap on the track, an edge-fade mask reflecting scroll position, arrows that appear only when the track actually overflows, and arrow-key movement that scrolls by one card and moves focus into it. The same primitive then serves the mobile table fallback so a narrow screen scrolls cards consistently everywhere. Effort: M. Risk if built badly: arrows shown on a desktop strip where the three cards already fit, or snap fighting a trackpad's free scrolling until the strip feels sticky and broken. Why: The site is full of horizontal strips of badges, and consistency there is most of what makes a catalog feel finished. Source: new-ideas-03-design.json

Profil Quick Win

Lighthouse Helper Directory

Details

A senior member can switch on a lighthouse flag declaring they are open to drop-in questions about specific topics — a region, an era of drops, a game — and appear in a small directory of available helpers with a response-time note they set themselves. A new member picks a lighthouse and sends one structured question; the lighthouse answers or declines, and unanswered questions expire. It is drop-in help, not a paired mentorship. Effort: M. Risk if built badly: a few lighthouses absorb every question and burn out, so per-topic caps, a queue, expiring questions and hiding stale flags are all required. Why: Expertise about regions and old drops is the scarcest resource on the site, and a directory makes it findable. Source: new-ideas-07-profile.json

Performance Quick Win

Mirror the badge art into our storage

Details

Every badge tile loads its image from a third-party CDN this project does not control, so a rate limit or a removed file there is a hole in the catalog with no fallback. At sync time, copy the 1x, 2x and 4x PNGs whose URLs badges already stores into a Supabase Storage bucket (roughly 1,400 small files) and serve them with a long cache header, keeping the original URL in the row as a fallback. Effort: M. Risk if built badly: a bucket that is not served through the same image path as today is worse than the CDN, so keep the original URL as the fallback until the copy is verified for every row. Why: The catalog's whole visual identity depends on another company's CDN staying up and staying unmetered. Source: new-ideas-08-performance.json
