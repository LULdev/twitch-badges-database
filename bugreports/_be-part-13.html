Weekly game mutators

Details

Every week the panel picks one mutator that changes the rules of an existing game for everyone - double-or-nothing blackjack, slots that pay on two of a kind with a halved bet, a roulette green-zero bonus - announced on the hub with the affected game and reverted automatically at the week's end. A mutator is a small server-side override read from the settings document by the resolver the games already use, so it needs no new game code. Effort: M. Risk if built badly: a mutator that improves expected value becomes a week-long farming route, so each one must be checked against the payout maths before it ships and the settings document must stay the only source so a bad one can be switched off mid-week. Why: The same 13 games every day is the arcade's biggest retention problem, and rule twists buy novelty without shipping new games. Source: new-ideas-05-addon.json

Career trophy room

Details

A profile section accumulates competitive results - Grand Prix placements, season championships, circuit wins, top reviewer marks - each as a dated trophy naming the event it came from, kept even after the season resets. It reads a small results table written when an event closes, so trophies survive both the seasonal reset and any pruning. Effort: M. Risk if built badly: trophy rows must be written only by the closing job, or a client can insert its own honours, and the room must not become a second leaderboard of badge counts. Why: Competitive results currently expire with the season, which makes winning something the site then forgets. Source: new-ideas-05-addon.json

Post-round skill diagnostic

Details

After a skill round that was lost, or that ended below a configured threshold, the result panel shows a short server-generated explanation of the decisive input - 'you called it at floor 6 with a 22 percent bust chance; cashing at floor 4 was the value line' - built from the recorded inputs and the same probability constants the engine used. It is generated for that round only, never stored as advice, and never shown for the luck games where no decision existed. Effort: M. Risk if built badly: an explanation that is wrong or post-hoc destroys trust, so only inputs with a known optimal line should produce a diagnostic and the rest must say there was no decision to review. Why: Skill games currently return a score and nothing else, so a loss teaches a player nothing about the next round. Source: new-ideas-05-addon.json
