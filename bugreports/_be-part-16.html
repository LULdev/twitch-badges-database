Admin Aufwändig

Infrastructure Quota and Cost Monitor

Details

A panel tab tracks the platform limits this project actually lives inside, covering Vercel Hobby function invocations and cron minutes, Supabase database size and egress, and the 60-second function budget, with a warning line before a limit is hit. It reads provider usage where exposed plus the sync heartbeats' recorded durations. Effort: M. Sonstiges Aufwändig

Per-source freshness SLO, exposed both to `/stats` and as curl-able JSON

Details

Define a maximum age per data source (catalog, drop windows, owner stats, per-user inventory) and derive a per-source status from the newest row each engine wrote — not from "did the cron tick". `/stats` shows the four staleness gauges next to the existing uptime meter, and `/api/health` returns the same structure as JSON so an external monitor or a GitHub Actions step can assert it. A source that is *ticking but stale* is the exact failure a heartbeat cannot see. Effort: S. Source: bugreports/agent-idea-09.md

Sonstiges Aufwändig

Sync cost and time budget guard (serverless wall clock + external call volume)

Details

Instrument each engine with its wall-clock time and its outbound call count, and assert both against an explicit budget derived from the platform limits (60 s per serverless invocation; a polite call ceiling for the ToS-sensitive providers). When a run approaches the budget it stops taking new work, commits what it has, and records a `partial` heartbeat instead of being killed mid-flight. The numbers are also the honest answer to "what does this cost on Hobby". Effort: M. Source: bugreports/agent-idea-09.md

XP Aufwändig

Discovery XP for First-Viewed Badges

Details

Reading a badge detail page the member has never viewed grants a small one-time XP such as +5, recorded per user and badge UUID so it can never pay twice, with a daily ceiling around 50 XP. It reads the existing page views and the badge catalog and gives signed-in readers a reason to explore the 476-badge archive rather than only the drop of the day. Effort: S. Risk if built badly: crawlers and refresh loops farm it, so it must be gated to a signed-in member, permanently deduplicated per badge, and capped per day. Why: The catalog is the site's whole asset, and this pays members for actually reading it. Source: new-ideas-10-xp-coin-admin.json

XP Aufwändig

Anti-Tilt Residual XP

Details

A member on a losing streak such as five consecutive losses in a day earns a small rising consolation XP on each further loss, so an unlucky session still moves the level bar, resetting on a win or at the daily reset and bounded by the game-XP cap. It is computed server-side from the streak of round outcomes. Effort: S. Risk if built badly: it pays members to lose deliberately, so the consolation must be worth far less than a win and must stop at a small daily ceiling. Why: It keeps a bad-luck evening from feeling like the site wasted the member's time. Source: new-ideas-10-xp-coin-admin.json
